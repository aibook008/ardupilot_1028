## 2. 技术需求与 APM 实现对照

### 2.1 飞控计算机硬件（§5.1.1.1）

| 协议要求 | APM 现状 | 差距 |
|---------|---------|------|
| 主 CPU ≥480MHz | CubeOrange STM32H7@480MHz ✅ / Pixhawk6X STM32H755@480MHz ✅ | 满足 |
| 从 CPU ≥24MHz | 协处理器 STM32F103@72MHz ✅ | 满足 |
| MEMS 惯导集成 | 内置三冗余 IMU（ICM-20689 + BMI055 + ICM-42688） ✅ | 满足 |
| 动静压采集 | 内置气压计（MS5611/ICP-20100），外部空速管 ✅ | 满足 |
| 看门狗 | `AP_Scheduler` 内置软件看门狗 ✅ | 满足 |
| CAN 总线 | DroneCAN (libcanard) ✅，双 CAN 口（取决于板型） | 满足 |
| ≥2kg 总重限制 | 飞控板本身 <500g ✅ | 满足 |
| -40°C~+60°C 工作温度 | 需定制工业级板（标准消费级 -20~+60°C） | ⚠️ 需定制 |
| 数据记录器 ≥8GB | microSD 卡槽 ✅，容量取决于卡 | 满足 |

**风险点**：宽温（-40°C）需定制工业级飞控板，标准 CubeOrange/Pixhawk6X 不满足。

### 2.3 转换模态控制（§5.1.3.4）

| 协议要求 | APM 实现 | 代码路径 | 状态 |
|---------|---------|---------|------|
| 冗余操纵控制分配 | `tilt_compensate_angle()` | `ArduPlane/tiltrotor.cpp:451-497` | ⚠️ 需验证 300kg 级适用性 |
| 转换过程姿态控制 | `SLT_Transition::update()` 三阶段状态机 | `ArduPlane/quadplane.cpp:1466-1671` | ⚠️ 需补充中断回退逻辑 |
| 高度/速度/航线控制 | 过渡期间混合固定翼+旋翼控制 | `quadplane.cpp` transition 分支 | ⚠️ 需调参验证 |
| 转换进入条件 | `Q_ASSIST_SPEED` 参数 | `ArduPlane/quadplane.cpp` | ✅ 有基础 |
| 转换中断判断 | **缺失**：无主动中断回退机制 | — | ❌ 需新增 |
| 安全性处理 | `Q_TRANS_FAIL_TMO` 超时降级 | `quadplane.cpp:1466-1671` | ⚠️ 需扩展 |

**核心风险**：协议明确要求"转换中断判断"，APM 当前仅有超时降级，缺乏主动中断回退（如空速不足时退回旋翼模式）。

### 2.5 CAAC 远程身份认证（§5.1.3.6）

| 协议要求 | APM 实现 | 状态 |
|---------|---------|------|
| 实名登记与激活校验 | **无** | ❌ 需从零开发 |
| 运行识别信息报送 | **无** | ❌ 需从零开发 |
| 广播式 Remote ID (BLE/WiFi) | **无** | ❌ 需集成外部模块 |
| 网络式 Remote ID (4G/5G→UOM) | **无** | ❌ 需开发蜂窝通信模块 |

**核心风险**：CAAC Remote ID 是**合规性硬需求**（GB 46761-2025、GB 46750-2025），APM 完全无此功能，需评估第三方模块或从零开发。工作量估计：2-3 人月。

### 2.7 仿真验证（§5.1.4）

| 协议要求 | APM 实现 | 状态 |
|---------|---------|------|
| 全流程飞行仿真 | SITL + JSBSim/MATLAB ✅ | 满足 |
| 控制参数拉偏 | 可改 `SIM_*` 参数 | ⚠️ 部分满足 |
| 升阻/舵效拉偏 | **内置模型不易拉偏**（`SIM_Plane.cpp` 硬编码气动系数） | ⚠️ 需改源码或用 MATLAB |
| 重心/重量拉偏 | `SIM_MASS` / `SIM_CG` 参数 | ✅ 满足 |
| 风扰动 | `SIM_WIND_SPD` / `SIM_WIND_DIR` | ✅ 满足 |
| 半物理仿真 | HIL 可通过 DroneCAN 连接 | ✅ 满足 |

**风险点**：鲁棒性仿真要求大量参数拉偏（升阻特性、舵效、旋翼拉力系数），APM 内置 `SIM_Plane.cpp` 模型硬编码气动系数，不易修改。建议使用 MATLAB/Simulink + JSON 接口做高保真仿真。

## 3. 风险矩阵

### 🔴 高风险（协议明确要求，APM 无实现或差距大）

| 风险 ID | 风险描述 | 协议章节 | 影响 | 建议对策 |
|---------|---------|---------|------|---------|
| R1 | CAAC Remote ID 合规 | §5.1.3.6 | 无法通过适航审查 | 评估第三方 Remote ID 模块（如 Dronetag、PingID）；预留开发时间 2-3 人月 |

## 7. 结论

ArduPilot 在**旋翼/固定翼控制、航线管理、故障安全、仿真框架**方面已具备坚实基础，可覆盖协议约 60-70% 的功能需求。主要差距集中在：

1. **CAAC 合规功能**（Remote ID、实名登记）—— 完全缺失，需从零开发或集成第三方模块
2. **转换安全逻辑**（中断回退、单电机失效）—— 有基础但不完整，需定制开发
3. **异常保护**（高度异常、失速）—— 缺失，需新增模块
4. **文档与示例**—— 无中文文档，需组织编写
5. **工业级硬件**—— 标准板不满足 -40°C，需定制

建议采用**分阶段迭代**策略：一期锁定硬件 + 设计，二期仿真验证，三期试飞调参，四期集成合规功能。优先解决高风险项（R1-R6），中低风险项可并行推进。
