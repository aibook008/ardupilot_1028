## 1. 本文目的

澄清三个被测试过程混淆的问题：

1. ArduPilot 里"控制律重构"（control reallocation）**在代码里的确切位置和触发条件**——它不依赖 Lua，从来不是 Lua 的事
2. 我们当前的验证方案（Lua 注入 + 脚本开 boost）**与飞控原生路径的逻辑对应关系**——Lua 只是测试激励，不是重构执行者
3. 正确的验证路径：**从飞控代码内部触发重构**（`thrust_loss_check` → `set_thrust_boost`），而不是让 Lua 参与控制链

## 2. 控制律重构的代码级对应

### 2.1 重构算法本体：`AP_MotorsMatrix::output_armed_stabilizing()`

控制律重构 = 混控器把失效电机从控制分配矩阵中摘除并重解。代码全部在 `libraries/AP_Motors/AP_MotorsMatrix.cpp` 的混控求解函数内（400Hz，每个主循环执行），**纯 C++，无 Lua 参与**：

| 重构动作 | 代码位置 | 作用 |
|---------|---------|------|
| 主分配段跳过失效电机 yaw 因子 | `AP_MotorsMatrix.cpp:313` | `_thrust_boost` 为 true 时，`_motor_lost_index` 那一列不参与 yaw 力矩分配 |
| yaw 裕度扩展 | :333 | boost 时 yaw 可用余量下限提到 50%（为重分配腾空间） |
| 失效电机推力的 yaw 约束重分配 | :339-352 | 失效电机的推力份额按剩余电机 yaw 裕度重解，裕度不足时裁剪 yaw 指令 |
| rpy_scale 求解排除失效电机 | :375-384 | 求饱和缩放系数时失效电机的输出不计入 `rpy_high`，**保住姿态控制权限不被裁剪**——这是重构在饱和工况下的核心价值 |
| 平滑过渡 | :232-237（`boost_ratio`） | `_thrust_boost_ratio` 0→1 渐变，重构生效/退出无突跳 |
| **注意（重要澄清）** | — | boost **不补推力**：丢失的 1/8 升力仍由高度环抬油门补（log 33 中 ThO 0.55→0.68）。重构保的是"7 电机下姿态/力矩分配的最优性"，不是总升力 |

### 2.2 重构的使能开关：`_thrust_boost`

`AP_Motors_Class.h:167-168`（`set/get_thrust_boost`）。只有它为 true 时上表的重构代码路径才激活。

### 2.3 重构的关闭（自愈）：混控器内部自动

`AP_MotorsMatrix.cpp:519-522`，每个混控周期检查：

```
油门有余量 && rpyt_high < 0.9 && _thrust_balanced  →  _thrust_boost = false
```

即：**推力不再紧张时重构自动退出**。这是"按需启用"设计——重构只在饱和边缘有意义。

### 2.4 失效检测（给重构提供失效电机号）：`check_for_failed_motor()`

`AP_MotorsMatrix.cpp:479`，每个混控周期在 `output_armed_stabilizing()` 末尾（:468）运行：

- 对 8 路混控指令做 0.5s 低通滤波，`thrust_balance = 最高滤波输出×电机数/总和`
- **≥1.5 持续** → 记 `_motor_lost_index`（推力最高的那个电机判失效）；≤1.25 恢复
- ≥6 电机才启用（:512）；**boost 激活期间索引锁定**（:500-502）
- 检测签名是"**某电机指令异常高**"（推力损失后姿态环把其余电机推高的结果）——不是"指令为零"

### 2.5 触发链（飞控代码内部，唯一正当路径）

```
真失效发生（堵转/掉桨 → 该电机不转，其余电机被姿态环推高补偿）
  → 推力不足、姿态误差 → 剩余电机指令饱和/接近饱和（rpyt_high→0.9+，limit 置位）
  → 【检测】check_for_failed_motor: thrust_balance≥1.5 → _motor_lost_index 锁定
  → 【触发】载具级任务（Copter: thrust_loss_check, crash_check.cpp:100；
            Plane: 本次移植的 QuadPlane::thrust_loss_check, quadplane.cpp）
            判据：姿态目标<15° + 油门≥90%/饱和 + 油门>25% + 持续下沉 + 姿态误差<30°，1s
            → motors->set_thrust_boost(true)
  → 【重构】混控器下周期起按 §2.1 重解分配，_thrust_boost_ratio 平滑建立
  → 【退出】推力恢复余量后混控器自愈关闭（:519-522）
```

**关键点：触发检测（§2.4）和触发条件（§2.5 判据链）都隐含"推力紧张"这一前提**——失效电机本该出力但不出力，其余电机被迫顶高。这是重构机制的设计工况，也是它存在的物理理由。

## 2A. "APM 的重构"是什么——与 PX4 分配矩阵重构的本质区别

> 前置阅读：[allocation_comparison_apm_px4.md](../allocation_comparison_apm_px4.md)（两边"分配矩阵"概念对照：PX4 的 mix 是物理有效性矩阵 B 的伪逆 B⁺，APM 的 `_roll/_pitch/_yaw_factor` 是直接写死的混控增益表，中间没有伪逆）

### 2A.1 先厘清"重构"一词的两层含义

| 层面 | PX4 | APM |
|------|-----|-----|
| **分配矩阵本身**（正常时的混控来源） | 物理有效性矩阵 B → 伪逆 B⁺，**计算出来**的 | 混控增益表（静态机架硬编码 / Lua 运行时写），**直接给定**的 |
| **失效后的"重构"**（本文主题） | **矩阵级**：把失效电机的 B 矩阵列清零 → 重新求伪逆 → 新的 B⁺——分配矩阵**重新计算**，维度实质降一 | **约束级**：混控增益表不变，只在求解循环内**跳过失效电机的参与项**（yaw 裕度、rpy_high、rpy_scale），并允许其输出超界 >1.0 |

### 2A.2 PX4 的分配矩阵重构（真正的矩阵重算）

PX4 v1.15.3 `src/modules/control_allocator/`，失效处理链：

1. **失效检测**：`ControlAllocator::check_for_motor_failures()`（ControlAllocator.cpp:718）——订阅 `failure_detector_status`，`CA_FAILURE_MODE` 参数控制（默认 `IGNORE`，可选 `REMOVE_FIRST_FAILING_MOTOR`，仅处理首次单电机失效）
2. **触发**：确认后置 `_handled_motor_failure_bitmask`（:735）+ 对每个 allocation 实例 `setHadActuatorFailure(true)`（:741）
3. **矩阵级重构**：`update_effectiveness_matrix_if_needed(MOTOR_ACTIVATION_UPDATE)`（:747）→ **把失效电机在有效性矩阵 B 中的那一列清零**（:545-560：`matrix(i, actuator_idx) = 0.0f` 遍历全部 6 轴）→ `ControlAllocationPseudoInverse::updatePseudoInverse()` **重新计算伪逆** → 新的混控矩阵
4. **输出置 NaN**：失效电机指令直接置 NaN（:676-678 `actuator_motors.control[motors_idx] = NAN`）——物理上该电机不再被驱动
5. **恢复**：失效位消失后清零 bitmask → 重新算 B⁺（:752-760）
6. **归一化冻结**：`_had_actuator_failure` 置位后跳过 RPY 归一化缩放更新（ControlAllocationPseudoInverse.cpp:62）——防止失效后矩阵尺度抖动

**特征**：重构发生在**分配矩阵的生成环节**，产出是一个新的、降维的 B⁺；解算公式 `u = B⁺·(τ−τ_trim)` 对新矩阵自然成立，力矩/推力期望在 7 电机的几何下重新最优分解。PX4 还配合顺序去饱和（`ControlAllocationSequentialDesaturation`）处理约束。

### 2A.3 APM 的 thrust boost"重构"（约束级排除，非矩阵重算）

APM 没有可重算的矩阵——混控增益表是给定的（静态表或 Lua 表）。失效时 `_thrust_boost=true` 做的事全部发生在 `output_armed_stabilizing()` 的**求解循环内部**（见 §2.1 表）：

1. 失效电机不参与 yaw 裕度计算（:313）——它的"房间"不算数
2. `rpy_high` 统计跳过失效电机（:375-384）——它不再抬高饱和缩放的分母
3. **允许失效电机输出 >1.0**（源码注释 ：287-289 直说）——它反正出不了力，指令超界换取其余电机不被 rpy_scale 裁剪
4. yaw headroom 抬到 50%（:333）+ `_thrust_boost_ratio` 平滑过渡（:232-237）

**特征**：混控表不动、维度不变（8 路照算照发），失效电机的影响被从**约束求解**中剔除。数学上这不是重算伪逆，而是"带失效排除项的约束松弛"。

### 2A.4 逐项对比

| 维度 | PX4（矩阵级重构） | APM（约束级排除） |
|------|------------------|------------------|
| 重构对象 | 有效性矩阵 B 的列 + 伪逆 B⁺ 重算 | 求解循环内的排除分支（矩阵/表不动） |
| 失效电机输出 | **NaN**（不驱动） | 照常输出指令（可 >1.0）——**仿真验证时需注意它仍会出力** |
| 推力缺口处理 | 新 B⁺ 对 7 电机几何**重新最优分解**（力矩+推力一起重解） | 推力缺口**不处理**（由高度环抬油门补），重构只保力矩分配不被裁剪 |
| 检测来源 | `failure_detector`（外部模块订阅） | `check_for_failed_motor`（混控器内建，指令分布签名） |
| 触发参数 | `CA_FAILURE_MODE`（默认 IGNORE） | Copter 默认开（FlightOption）；Plane 本次移植 `Q_TLOSS_ENABLE` |
| 处理范围 | 仅首次单电机失效（`REMOVE_FIRST_FAILING_MOTOR`） | 单失效；`_motor_lost_index` 唯一 |
| 恢复 | bitmask 清零→重算 B⁺ | balance≤1.25 自愈 + boost_ratio 平滑退出 |
| 数学性质 | 全局最优（最小二乘伪逆） | 启发式（yaw 裕度贪心 + 缩放保姿态） |
| 对 DF-200 的适用性 | 需迁移到 ControlAllocator 架构（大改） | **已内置**（§2.1 三处插入点随 AP_MotorsMatrix 编译即得） |

### 2A.5 对本项目的结论

1. **名称澄清**：APM 的 thrust boost 严格说是"**失效感知的约束重分配**"（failure-aware constraint reallocation），不是 PX4 意义上的"分配矩阵重构"。文档与汇报中使用"重构"一词时需注明此差别，避免甲方按 PX4 的语义（重算伪逆、最优解）预期 APM 的行为
2. **能力边界**：APM 方案不重新最优分解推力，总升力缺口永远靠高度环——这在 8 桨冗余下够用（log 36：油门 0.49→0.61），但在推力极限工况（单桨失效+满载+高温）会比 PX4 的矩阵重解更早触到饱和
3. **验证口径**：本项目的验证目标是"APM 语义的重构"（约束级排除对姿态权限的保护，§4），不能用 PX4 语义（推力重最优分解）的预期去评判 log 数据——这正是此前多轮测试"感觉没起作用"的深层原因之一
4. **若需要 PX4 语义**：DF-200 的 Lua Dynamic 矩阵（§第4层）是唯一可做"运行时矩阵重构"的挂点——失效时 Lua 清零该电机因子列并重新归一化，等效 PX4 的列清零+重算；但那是定制开发（§5 清单第 4 层），且与内建 thrust boost 叠加的交互需验证（failure_analysis.md §3.5.1 第 5 点）

## 3. 当前验证方案与原生路径的逻辑对应

### 3.1 职责划分（正确架构）

```
┌─ 飞控代码（控制链，实机不变）─────────────────────────┐
│  check_for_failed_motor  检测失效电机号（混控层）      │
│  QuadPlane::thrust_loss_check  触发判断（本次移植）    │
│  set_thrust_boost → 重构算法（§2.1）                   │
└───────────────────────────────────────────────────────┘
            ▲
            │ 只有这一条触发路径（Q_TLOSS_ENABLE=1 时）
┌─ 测试激励（SITL 专用，不参与控制）────────────────────┐
│  df200_motor_matrix.lua：因子表唯一写者，              │
│    SCR_USER1=1 时把目标电机因子清零（模拟该电机"消失"）│
│  motor_failure_test_param.lua：MOT_STOP_BITMASK 参数  │
│    管理 + boost 开关（仅 Q_TLOSS_ENABLE=0 的注入测试   │
│    时直控 boost；真机路径闲置）                        │
└───────────────────────────────────────────────────────┘
```

- **Lua 不重构控制律**。因子清零只是"让混控器看到该电机不存在"的模拟手段，等价于物理上拆掉一只桨。重构算法本体始终是 §2.1 的 C++ 代码
- Lua 的 `set_thrust_boost(true)` 只是**测试快捷方式**（跳过触发判据直接激活重构），用于隔离变量；真机上唯一触发方是 `thrust_loss_check`

### 3.2 三轮测试为何都没观察到重构生效（根因链）

| log | 注入方式 | 检测是否触发 | boost 是否持续 | 重构是否生效 | 根因 |
|-----|---------|-------------|---------------|-------------|------|
| 30 | PWM 覆盖（C6 钉 1000） | 否 | 否 | 否 | 混控器不知情，分配照旧，纯姿态环硬顶 |

| 33 | **因子清零**（混控级）+ 脚本直开 boost | 否** | 否（0/406 样本） | 等效否 | 同上：悬停裕度下自愈条件全满足，boost 活不过 1 个混控周期 |

### 3.3 从数据确认重构是否在跑的判据（后续测试用）

| 信号 | 位置 | 判据 |
|------|------|------|
| `MOTB.FailFlags` bit0 | `AP_MotorsMulticopter.cpp:398`（10Hz） | `=1` 表示 boost 持续激活——**重构在跑的直接证据**（log 33 为 0/406，未跑） |

## 4. 正确的验证路径（结论）

测试目的：验证单桨失效下"控制律重构"的有效性。则：

1. **触发必须走飞控代码路径**：`Q_TLOSS_ENABLE=1`，`QuadPlane::thrust_loss_check` 是唯一触发方。Lua 只做失效模拟（因子清零），不碰 boost——这就是当前代码的最终形态，测试脚本 v6 中的 boost 直控在正式验证时应闲置（或删除）
2. **工况必须喂到重构的设计点**：推力紧张（7 电机接近饱和）。手段：
   - 加大模型质量至 7 电机悬停 ThO≈0.9+（df200.json/SIM 质量参数，改配置不改代码），或
   - 悬停时叠加持续姿态指令逼出 rpyt 饱和
   此时自愈条件不满足 → boost 持续 ON（`MOTB.FailFlags bit0=1` 可验证）→ 重构真实运行
3. **对比组**：同工况、同注入，`thrust_loss_check` 使能 vs 关闭（或boost 常开 vs 常关），对比指标为姿态跟踪误差与 rpy 裁剪（§3.3 表）
4. **预期结果**：饱和工况下，重构组姿态控制权限被保住（rpy_scale 不裁剪姿态、姿态误差小）；非重构组失效电机列占用分配矩阵导致裁剪、姿态发散风险。**悬停轻载工况下两者无差异是预期内的（机制按需退出），不作为有效性判据**

## 4A. 物理层失效注入验证（log 35/36，2026-10-19）与检测-触发分工详解

### 4A.1 注入方式演进：为什么必须物理层

前三轮测试（log 30/31/33）的教训收敛为一个结论：**注入必须发生在推力产生层，且"混控器指令"与"物理出力"必须脱钩**。最终方案：

| 层 | 手段 | 效果 |
|----|------|------|
| **SIM 物理层（最终方案）** | `SIM_MOT_FAIL` bitmask（`SITL.cpp` index 50，消费点 `SIM_Frame.cpp:675`），命中电机推力/扭矩/rpm 全归零 | 混控器照常给失效电机发指令（MOTT.Mot2 显示 0.768 正常指令值），物理上不出力——**真故障等价**，检测签名自然成立 |
| ~~Lua 因子清零~~（已废弃） | `load_factors` 该电机因子置 0 | 误导：混控器指令归 0（"电机被拆"），`check_for_failed_motor` 签名（指令异常高）永不成立 |
| ~~PWM 输出覆盖~~（已废弃） | `set_output_pwm_chan_timeout` 钉 PWM_MIN | 混控器完全不知情，什么都不会发生 |

**实现 bug 记录**：第一版 `SIM_Mot_Fail` 消费点用了 `1U << (motor_offset + i)`（motor_offset=4 是 servo 槽位偏移），bit 位置错位导致掩码永不命中（log 35 注入无反应的根因）。修正为 `1U << i`（bit0=电机1）。

### 4A.2 log 36 结果：物理失效 + 补偿闭环全链生效

`SIM_MOT_FAIL=2` 全程注入，GUIDED 起飞+机动+悬停 ~50s：

| 指标 | 数值 | 解读 |
|------|------|------|
| MOTT.M2（死桨指令） | **0.768 均值 / 1.000 峰值** | 混控器仍把它当**最高指令电机**——这正是重构算法注释（`AP_MotorsMatrix.cpp:287-289`）设计的失效签名："remove the highest motor output ... let that motor go greater than 1.0" |
| 其余 7 电机 | 0.399-0.714，饱和率 71% | 姿态环+高度环把 1/8 推力缺口分摊：ThO 0.49→0.61，对侧/邻位电机（M4/M6）抬升最多 |
| 姿态 | Roll 瞬态 max 6.7°，稳态 <1° | 8 桨冗余下闭环可控 |
| 高度 | 10.07m 稳定 | 高度环完全兜住 |
| **检测** | **未触发**（boost 0/145） | 两个阈值差一点，见 4A.3 |

### 4A.3 检测链两级未触发的原因与阈值分析

失效发生后的"检测之后的工作"分两级，各有独立的判据和作用：

**第 1 级：`check_for_failed_motor()`（混控层，400Hz）——识别失效电机号**

- 判据：`thrust_balance = rpyt_high × N / Σ输出 ≥ 1.5`（≥6 电机启用）
- log 36 实测：`0.768×8/4.468 = 1.375` —— **差 8% 未触发**
- **好处/作用**：
  1. 输出 `_motor_lost_index`——**重构算法的失效电机号来源**，boost 激活期间锁定该索引（:500-502），所有"排除失效电机"的分支（:313/:375-384）都以它为准
  2. 每 400Hz 运行、0.5s 滤波——比载具级检测快一个数量级，且**自动跟踪失效电机的恢复**（balance≤1.25 自愈），无需载具层参与
  3. 零成本运行（混控周期内顺手算），不占调度表
- **局限**：签名是"指令异常高"，只有姿态环把其余电机推高后才成立——**天然滞后于失效**（依赖闭环反应时间）；且对多余度构型（8 桨失 1 桨补偿太均匀，1.375<1.5）阈值偏严
- **阈值修正建议**：1.5→1.25（正常均衡飞行 ≈1.0-1.1，1.25 不会误报）；或参数化

**第 2 级：`thrust_loss_check()`（载具层，10Hz）——状态级确认与 boost 触发**

- 判据链：姿态目标<15° + 油门≥0.9 或饱和 + 油门>0.25 + 持续下沉 + 姿态误差<30°，持续 1s
- log 36 实测：ThO 均值 0.614 / max 0.657 —— **油门判据（≥0.9）远未满足**
- **作用（与第 1 级互补）**：
  1. **状态级确认**：第 1 级只看"指令分布异常"，可能被激进机动（大姿态指令导致某电机瞬间最高）误标；第 2 级用**飞行动态**（饱和+下沉+姿态仍可控）交叉验证，**确认这是真推力损失而非分配假象**，才置 `set_thrust_boost(true)`——防止重构被误触发
  2. **告警与记录**：EMERGENCY GCS 消息（带失效电机号）+ ERR 日志（subsys 25）——通知机组/记录仪
  3. boost 一经触发由第 1 级所在混控器接管：重构持续运行、自愈退出（油门恢复余量时）
- **局限**：0.9 油门阈值按 4 轴/6 轴标定（失 1/4、1/6 推力油门必顶满）；**8 轴失 1 桨油门 0.49→0.61 永远到不了 0.9**——该判据在多余度构型下结构性失效
- **阈值修正建议**：`Q_TLOSS_THR` 参数化（默认 0.9 保持原生语义，DF-200 设 ~0.55）

**两级的关系**：第 1 级负责"**哪个电机**"（提供 index 给重构），第 2 级负责"**是否真的失效了**"（状态确认 + 授权 boost）。真机上理想流程是两者与门：第 1 级给出候选索引 → 第 2 级状态确认 → boost 开 → 重构按索引执行。当前代码是"或"的关系（第 2 级触发时索引可能来自第 1 级，也可能过时）——阈值修正后应验证索引一致性。

### 4A.4 触发后的完整工作序列（阈值修正后预期）

```
SIM_MOT_FAIL=2 关桨
  → 姿态环推高其余电机（M2 成为最高指令，0.768）         [log36 已证]
  → 第 1 级：balance≥阈值 → _motor_lost_index=1          [待阈值 1.25 修正]
  → 第 2 级：thrust_loss_check 判据满足 1s → boost ON    [待油门阈值修正]
  → 重构生效：
      - yaw 裕度计算跳过 M2（:313）
      - rpy_high 统计跳过 M2（:375-384）→ 其余电机不被 M2 的高指令拖累裁剪
      - M2 允许 >1.0（物理上它不出力，指令超界无害）
  → MOTB.FailFlags bit0=1 可观测
  → 失效恢复（SIM_MOT_FAIL=0）：balance 回落 → boost 自愈关闭 → 因子表恢复正常
```
