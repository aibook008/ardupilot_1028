## 2. 已完成的分析

数据：`logs/00000006.BIN` 与本次运行的 `/tmp/df200_rotor.log`，rotor 采样约 20 Hz。
功率脚本为 [df200_power_analysis.py](scripts/df200_power_analysis.py)，输出为：

- [df200_power_corridor.md](df200_power_corridor.md)：阶段功率、各电机拉力均值与峰值、功率图。
- [df200_power_00000006.csv](df200_power_00000006.csv)：功率时序；本次以 `--smooth 0.5` 生成，功率列经过平滑，不能用它替代原始功率统计瞬时峰值。
- `df200_power_imgs/`：四张功率图。

复算命令（必须先确认临时 rotor 文件仍与 BIN 配对）：

```bash
MPLCONFIGDIR=/tmp/mplconfig-power python3 docs/scripts/df200_power_analysis.py \
  logs/00000006.BIN --rotor /tmp/df200_rotor.log \
  --report docs/df200_power_corridor.md \
  --csv docs/df200_power_00000006.csv --smooth 0.5
```

功率为逐桨查表之和。内桨以桨轴来流 `velin` 而非整机空速查表；来流超过 50 m/s
按当前 C++ 实现钳位。外桨使用静态转速功率表。它与 SITL 电流计算使用同一模型，
这种一致性不是独立的实物精度验证。

脚本已更新电机表、返航阶段识别、实际着陆下降边界及八电机拉力表。
曾将正向过渡完成后的所有数据归为巡航，现已拆开，不能复用旧巡航统计。

## 4. 起飞峰值证据与用户目标

用户要求正常垂起 ≤90 kW、短时峰值 ≤110 kW；短时允许时间尚未被用户明确规定。

| 阶段 | 峰值及时间 | >90 kW 累计时长 | >110 kW 累计时长 |
|---|---|---:|---:|
| 起飞爬升 | 148.45 kW @ 84.05 s | 0.68 s | 0.45 s |
| 正向过渡 | 102.68 kW @ 151.00 s | 7.07 s | 0 |
| VTOL 进近 | 138.34 kW @ 330.35 s | 2.19 s | 0.78 s |
| 着陆下降 | 84.51 kW @ 344.80 s | 0 | 0 |

按原始功率采样在阈值处线性插值：起飞连续超过 110 kW 为 83.738–84.184 s，
约 0.446 s；进近包含最大峰值的一次为 330.233–330.711 s，约 0.478 s，
进近累计 0.782 s 来自多次超限。采样周期约 0.05 s，插值不代表更高的测量时间分辨率。

以各自最大功率的 95% 定义峰顶宽度，起飞约 0.135 s，进近约 0.085 s。
报告持续时间必须明确是阈值超限、峰顶宽度、单次连续时间还是累计时间。

起飞控制证据：

- BIN 参数 `Q_PILOT_ACCEL_Z=0.8 m/s²`，`Q_PILOT_SPD_UP=1 m/s`，`Q_WP_SPEED_UP=100 cm/s`，`Q_WP_ACCEL_Z=50 cm/s²`。
- `PSCD` 使用向下为正：起飞规划向上加速度最大约 0.8 m/s²，叠加反馈后的目标最大约 8.09 m/s²。
- 84.04 s 附近高度误差约 0.93 m；实际最大爬升速度约 2.24 m/s，超过原定 1 m/s。
- 84.05 s 八电机 cmd 约 0.99–1.00，功率内桨约 42.10 kW、外桨约 106.35 kW。
- 86–133 s 稳定爬升约 80 kW，本次高峰集中在起飞初始过程。

这支持“离地前轨迹已开始上升，反馈修正使最终加速度目标过大”的分析，
但不能据此断言某项尚未实施的改动必然满足 110 kW。

## 5. 正在讨论的修改：尚未实现

用户倾向于直接在每个控制节拍的最后限制最终向上加速度目标。
逐节拍限幅与逐节拍重新初始化 PID 是两回事，前者可行，后者会反复清掉所需控制状态。

调用链：`QuadPlane::takeoff_controller()` → `set_climb_rate_cms()` →
`AC_PosControl::input_vel_accel_z()`；随后 `run_z_controller()` →
`AC_PosControl::update_z_controller()`。

当前起飞路径的轨迹加速度使用 `Q_PILOT_ACCEL_Z`，不能只改 `Q_WP_ACCEL_Z`。
最终目标应在 `update_z_controller()` 中 `_accel_target.z` 叠加
`_accel_desired.z + _accel_offset.z + _accel_terrain` 之后、加速度 PID 之前限幅。
该处向上为正、单位 cm/s²，50 对应净向上加速度 0.5 m/s²，不额外加重力。

建议先仅起飞阶段逐节拍施加最终目标上限，保留控制器状态，并正确反馈饱和，
避免上游轨迹和速度积分持续积累。不要把最终目标被限幅等同于必须清掉加速度环积分；
后者仍承担支撑重量所需的油门。起飞结束后不可残留限幅影响过渡或着陆。

讨论过的地面准备／离地状态机属于备选方案，不是已实现内容，也不是用户确认必须采用的方案。
0.5 m/s² 是候选值，未修改当前默认参数，未编译或飞行验证。

以当前表、约 380 kg、日志附近空气密度、低来流、八桨相同 cmd 的理想垂直均衡工况估算：

| 工况 | 电功率 | 净向上加速度 |
|---|---:|---:|
| 支撑重量 | 约 79.5 kW | 0 |
| 候选起飞目标 | 约 85.6 kW | 0.5 m/s² |
| 90 kW | 90 kW | 约 0.85 m/s² |
| 110 kW | 110 kW | 约 2.3 m/s² |

这些是查表的平衡估算，不是闭环动态上界。加速度 PID 的超调、姿态补偿、差动输出
仍可增加瞬时电功率。用户是否需要严格功率硬限制应结合其后续指令处理，
不能将加速度目标限幅宣称为严格的功率保证。
