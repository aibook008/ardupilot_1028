# ArduPilot 倾转旋翼 SIL / HIL 联仿需求说明（对外）

> 代码版本：Plane 4.6.x。  
> 目的：向外部仿真/动力学方说明联仿边界、通信差异与分阶段交付。  
> 详细技术实现见：`APM-MATLAB联合仿真.md`、`APM-SITL仿真体系与JSBSim.md`、`docs/vtol_hitl.md`。  
> 2026-09-29 更新：新增 §5「拉偏测试、全流程串联与整合 UI」需求；原 §5–§7 顺延为 §6–§8。

---

## 1. 项目目标

验证倾转旋翼 / QuadPlane 在真实 ArduPilot 控制律下的闭环行为。联仿分两阶段 + 一项 SITL 扩展（阶段一打通后启动，详见 §5）：

| 阶段 | 名称 | 目标 | 飞控跑在哪 | 外部仿真机职责 |
|:--:|------|------|------------|----------------|
| **一** | **SIL 消息流打通** | 先跑通“指令 ↔ 状态”闭环与仿真环境 | PC 上 SITL 进程 | 提供动力学 + 环境，按约定协议回传状态 |
| **一+** | **拉偏 / 全流程 / 整合 UI** | 鲁棒性拉偏矩阵 + 全链自动化测试 + 图形化整合版本 | PC 上 SITL 进程 | 模型运行时可拉偏、可脚本化受控（详见 §5） |
| **二** | **HIL 真机串口闭环** | 在真实飞控硬件上验证 IO/时序/链路 | 真飞控板（如 Pixhawk） | 仍提供动力学 + 环境，经**串口**闭环 |

**阶段一成功标准**：能稳定收发、锁步/近实时不卡死、可解锁与基本模式切换；**不要求**一开始就把高保真气动/天气模型做全。  
**阶段二**在阶段一协议与字段对齐后再启动。

---

## 2. 关键前提：SIL 与 HIL 通信方式不同

| | 阶段一 SIL（外部联仿） | 阶段二 HIL（经典串口） |
|--|------------------------|------------------------|
| 飞控侧 | PC 进程 `arduplane`（真实固件逻辑） | 真 MCU 固件 |
| 物理链路 | **网口 UDP/TCP** | **飞控 UART / USB-串口** |
| 典型协议 | SITL `JSON` / JSBSim / AirSim 桥 | **MAVLink HIL**（或双方约定的串口帧） |
| 交换内容 | PWM/执行器指令 ↔ 传感器与机体状态 | 执行器指令 ↔ 传感器与机体状态 |
| 与板内 SimOnHW 关系 | 无关 | **不同**：SimOnHW 用板内 SITL 模型，可不接外部动力学机 |

> 请勿按“同一套协议换个口”理解。SIL 打通后，HIL 仍需单独约定串口协议、波特率与时序。

## 3. 职责边界

### 3.1 我方（飞控 / ArduPilot）

- 提供并运行 ArduPilot Plane（含倾转/VTOL 相关模式与参数基线）。
- 阶段一：提供 SITL 侧桥接（优先 `JSON` 对接 MATLAB；也可 JSBSim / AirSim）。
- 阶段二：提供真飞控板、串口物理连接与固件侧 HIL 接入方案。
- 负责飞控侧：EKF、控制律、飞行模式、任务、故障保护、GCS（MAVProxy/QGC）。
- 给出接口字段表、联调步骤、验收用例。
- 阶段一+：拉偏矩阵调度、全流程任务（mission）设计与里程碑判据、结果归档；整合 UI 的需求与验收（脚本版已在内部跑通，见 `docs/df200_bias_sim.md`）。

### 3.2 对方（动力学 / 仿真环境）

- **提供飞行动力学模型**（六自由度或等效）：接收执行器指令，积分得到姿态/速度/位置等。
- **提供环境条件接口**（至少可配置，阶段一可先简化）：
  - 风速 / 风向（机体或 NED）；
  - 可选：阵风、湍流、温度、气压基准、起飞点海拔等。
- 按约定协议回传传感器/状态包；保证时间戳单调、锁步时每拍必回。
- **模型拉偏能力**：气动 / 舵效 / 重量重心 / 风场等参数运行时可注入、默认值基线零漂移（详见 §5.1）。
- 配合全流程自动化：模型进程可被脚本拉起 / 停止 / 清态，支持任务级连续飞行与超实时运行（详见 §5.2–5.3）。
- 阶段二配合串口侧收发与超时/重连策略。

### 3.3 阶段一对方**暂不必须**做到的

- 完整高保真气动数据库、全包线验证；
- 复杂天气场景（结冰、强对流等）；
- 视景/场景渲染（除非选 AirSim 且双方同意）；
- GPS/罗盘/气压计硬件级仿真细节（JSON 路径下飞控常由位置/姿态内部生成部分传感器，见现有 MATLAB 文档）。
- 模型拉偏接口（§5）——阶段一消息流验收后再交付，但请提前评估各项可行性并回复（见 §7 清单第 8 项）。

## 4. 阶段一（SIL）：消息流与环境打通

### 4.1 推荐对接路径（按优先级）

1. **MATLAB/Simulink + SITL `JSON`（推荐首选）**  
   - 文档：`APM-MATLAB联合仿真.md`  
   - 链路：UDP；SITL → 仿真机二进制 PWM 包（默认端口 **9002**）；仿真机 → SITL 一行 JSON 状态。  
   - 特点：**锁步**，利于复现与排障。

2. **JSBSim**  
   - 文档：`APM-SITL仿真体系与JSBSim.md`  
   - 链路：TCP 控制台 + UDP fgFDM；SITL 可拉起 JSBSim 子进程。

3. **AirSim**  
   - 适用于需要场景/视景时；接口见 `libraries/SITL/SIM_AirSim.*`。

> 阶段一请先选定**一种**路径打通；不要并行多套协议。

### 4.2 最小数据接口（阶段一必通）

**飞控 → 仿真机（每拍）**

| 内容 | 说明 |
|------|------|
| 执行器指令 | 典型 16 路 PWM（µs，约 1000–2000）；含倾转/电机/气动舵面通道映射需双方对齐表 |
| 帧序号 / 建议步频 | 用于丢帧、重复帧、重启检测（JSON 路径有 `frame_count` / `frame_rate`） |

**仿真机 → 飞控（每拍，最小集）**

| 字段 | 含义 | 备注 |
|------|------|------|
| `timestamp` | 仿真时间 | 单调递增 |
| `imu.gyro` | 角速度 | 机体系，rad/s |
| `imu.accel_body` | 比力/加速度 | 机体系，m/s² |
| `attitude` 或 `quaternion` | 姿态 | 二者择一 |
| `velocity` | 速度 | NED，m/s |
| `position` | 相对起飞点位移 | NED，m |

**环境（阶段一建议就预留，可先给常值）**

| 字段 | 含义 | 阶段一要求 |
|------|------|------------|
| 风速矢量或风速+风向 | 风场 | **可配置**；初值可为 0 |
| （可选）`airspeed` | 空速 | 有则直接用，无则可由速度推算 |
| （可选）起飞点经纬高/航向 | 原点 | 与 SITL `--home` 一致 |

通道映射（倾转舵机、电机、气动舵面编号）在联调前用一张表锁定，避免“消息通了但飞机飞不对”。

### 4.3 阶段一验收（消息流 / 环境）

1. **链路**：连续 ≥10 min 无协议卡死；锁步路径下飞控步频稳定。  
2. **字段**：最小状态集齐全；错误包可检出（magic/长度/JSON 解析失败有日志）。  
3. **控制**：可解锁；至少一种 VTOL/固定翼相关模式能切到并保持；油门/倾转通道变化时仿真状态有合理响应。  
4. **环境**：风速设为 0 与设为非 0（如 5 m/s）时，状态响应可区分（阶段一不要求气动精度）。  
5. **记录**：双方能保存同一段日志（飞控 DataFlash/MAVLink + 仿真侧 CSV/MAT），便于对照。

## 5. 阶段一扩展（SIL）：拉偏测试、全流程串联与整合 UI

> 前置：阶段一消息流验收通过后启动。内部已用 SITL 内置动力学完成同构验证（DF-200 拉偏流水线：SIM_AERO 十参数 + mission 5 件套 + 矩阵脚本，见 `docs/df200_bias_sim.md`）；本节把该能力固化为对外需求——**对方动力学模型需提供同等的运行时拉偏与脚本化受控能力**，以便在 SIL 层完成拉偏矩阵与全流程测试。

### 5.1 拉偏维度与幅度（对齐《仿真测试计划》SIM-RB）

| 维度 | 拉偏项 | 幅度初值（SIM-RB） | 内部实践参考 | 对应用例 |
|------|--------|--------------------|--------------|----------|
| 升阻特性 | 升力线斜率 / 零升阻力 / 诱导阻力 / 纵向静稳定 | ±15% | ±20~30%（`SIM_AERO_CLA/CD0/IND/CMA_SCL`） | SIM-RB-02 |
| 舵效 | 升降 / 副翼 / 方向 | ±15% | −30%（`SIM_AERO_ELE/AIL/RUD_SCL`） | SIM-RB-03 |
| 动力 | 旋翼拉力系数 | ±10% | （内部为桨表模型，暂未开放） | SIM-RB-04 |
| 重量重心 | 整机质量 / 惯量 / 重心前后 | 质量 ±10%；重心至包线极限 | `SIM_MASS_SCL`(+15%)、`SIM_INERTIA_SCL`(+30%)、`SIM_AERO_CGX_OFF`(+8cm) | SIM-RB-05/06 |
| 风场 | 常值风速/风向、阵风、湍流 | 5–10 m/s + 阵风 | `SIM_WIND_SPD/DIR/TURB`（转换段强制加风用例联动） | SIM-RB-07 |
| 控制律 | MC/FW PID | ±20% | 直接拉偏我方参数包，**无需对方支持** | SIM-RB-01 |

要求：

1. **运行时可注入**：拉偏以参数/接口方式注入即生效（内部先例：飞行中 PARAM_SET 改 `SIM_WIND_SPD`），不要求 per-case 重编译模型或修改配置文件。
2. **基线零漂移**：拉偏量处于默认值（缩放 1.0 / 增量 0.0）时，模型行为与未加机制前逐位一致——缩放乘在消费点，不改基准标定值。
3. **覆盖全流程**：拉偏不是单科目局部行为——同一 case 的拉偏须在 §5.2 全流程任务中生效，"拉偏 + 全链"可组合一键执行。
4. **幅度阶梯**：每项至少提供 标称 / 中档 / 包线 三档；包线档允许"完成转换或安全 ABORT"作为合格结果（对齐 SIM-RB 判据），但不允许失控发散。

### 5.2 全流程串联测试（对齐 SIM-E2E）

| 编号 | 场景 | 期望 |
|------|------|------|
| E2E-01 | 垂起→定点→正向转换→固定翼航线→反向转换→返场→垂直降落 | 全程自动可完成；日志含完整 σ/μ/阶段链 |
| E2E-02 | 同 E2E-01，中途注入 ABORT（空速不足或人工中断开关） | 安全回退并降落；ABORT 后无自动重转 |

要求：

1. **任务级执行**：全流程以 mission（航点任务）文件描述、脚本上传自动执行，不依赖人工遥控；反向转换等由任务触发的链路（如 RTL 返航触发）须在 mission 设计中保证触发条件（航向对准、直线段长度）。
2. **里程碑判据**：PASS/FAIL 以离散里程碑判定（起飞完成 / 转换完成 / 航点到达 / 降落 disarm、无 crash）；姿态/掉高等连续指标记录进档案供离线分析，**不做在线超差判废**（内部定版原则）。
3. **拉偏组合**：任一拉偏 case 均可在全流程任务上运行（§5.1 第 3 条）。

### 5.3 批量运行（矩阵）与结果档案

内部参考实现：`docs/scripts/df200_case_run.py` 单脚本闭环（连接→注参→上传 mission→AUTO→arm→监控 STATUSTEXT 至 disarm→归档），`--matrix` 模式逐 case 顺序执行、每 case 前重启 SITL 清态，结束出 summary 汇总表。

| 项 | 要求 |
|----|------|
| 隔离 | 每 case 干净起步：模型与参数状态清零（等效 wipe），杜绝跨 case 参数残留 |
| 注入校验 | 拉偏参数写入后带回读校验；重试后仍不齐则该 case 判 FAIL，不静默跳过 |
| 失败隔离 | 单 case FAIL 只记录不中断矩阵；进程级强杀兜底，防 hang 阻塞后续 case |
| 超时 | 每 case 显式超时兜底（按任务时长 + 余量），超时判 FAIL 并归档现场 |
| 结果档案 | 每 case 独立目录：运行日志 + 飞行数据日志（DataFlash/CSV/MAT）+ `result.json`（case 配置/参数/里程碑时间线/status） |
| 汇总 | 矩阵结束输出 summary 表（case × status × 里程碑齐套数）；**拉偏系列整体通过率 ≥80%、失败项有分析**（出门准则，对齐《仿真测试计划》§6.2） |
| 可重复 | 关键 case ≥3 次结果一致（对齐通用通过准则） |

### 5.4 整合 UI 版本

在脚本版（内部已跑通）之上，提供图形化整合版本，把"配置 → 执行 → 监控 → 归档 → 分析"收进单一界面：

| 功能块 | 最低要求 |
|--------|----------|
| 配置 | 拉偏矩阵可视化编辑（维度/幅度/mission 选择），方案可存为文件并版本入库 |
| 执行 | 一键跑批 / 单 case 执行；显示当前 case 进度与 SITL/模型进程状态 |
| 监控 | 实时状态：模式、姿态/高度/空速、阶段枚举、里程碑事件流（STATUSTEXT 级）；crash/FAIL 高亮 |
| 归档 | 自动按 case 归档日志与 result.json；summary 可查看/导出 |
| 分析 | （可选增强）单 case 关键曲线（σ/μ、姿态、掉高）与里程碑时间线回看；接入离线分析脚本输出摘要 |
| 复现 | 任一历史 case 可从档案一键重放/重跑 |

约束：实现形态不限（桌面 GUI / Web 均可），但必须**复用 §5.3 同一套调度与档案结构**——UI 是脚本层的封装，不引入第二套判据或数据格式。节奏：阶段一+ 先交付脚本版 + 方案文件，UI 版并行开发、HIL 启动前完成验收。

### 5.5 扩展验收

1. **拉偏生效性**：同一 case 拉偏前后状态响应可区分（如升阻 +30% 后巡航油门/姿态可见变化），恢复默认后与基线一致。
2. **全流程**：E2E-01 在基线与至少 3 个拉偏 case 下均可完成。
3. **矩阵**：≥10 case 一键跑完，summary 与逐 case 档案齐套；中途 kill 单 case 不影响其余 case 档案完整性。
4. **UI**：以 UI 完成"编辑方案 → 跑批 → 查看 summary → 打开单 case 档案"闭环，产出档案与脚本版格式一致、互相可读。

## 6. 阶段二（HIL）：真飞控串口闭环（概要）

在阶段一字段与通道映射稳定后启动。

| 项 | 要求 |
|----|------|
| 硬件 | 目标飞控板 + PC（跑仿真机） |
| 物理口 | 飞控 **UART 或 USB-CDC 串口** 至 PC |
| 协议 | 优先 **MAVLink HIL**（执行器指令 ↔ 传感器/状态）；若用自定义帧须书面约定 |
| 待双方确认 | 波特率、端口、锁步或实时、超时重发、CRC、通道顺序与 SIL 是否一致 |
| 验收方向 | 真板调度下闭环可飞；串口负载与延迟可接受；与 SIL 同场景趋势一致 |

> 板内 **SimOnHW**（`docs/vtol_hitl.md`）是另一条 HITL 路径：动力学在板内，**不替代**本阶段“串口外接外部仿真机”的需求。

## 7. 请对方确认 / 回复的清单

请直接回复下列选项，便于排期：

1. 阶段一仿真引擎：**MATLAB / JSBSim / AirSim / 其他（请写明）**  
2. 是否接受阶段一走 **SITL JSON 锁步**（推荐）  
3. 动力学模型当前成熟度：仅刚体 / 已有气动 / 含推进与倾转  
4. 风场接口：常值风是否够用阶段一；阵风/湍流是否阶段二再做  
5. 执行器通道数与映射表负责人（谁出第一版）  
6. 阶段二串口：是否按 MAVLink HIL；目标波特率  
7. 联调环境：同机还是跨机 IP；防火墙/端口是否可开 9002 等  
8. 阶段一+拉偏能力（详见 §5）：§5.1 各维度（升阻/舵效/重量重心/风场/动力）哪些已可运行时注入、哪些需开发；幅度阶梯（标称/中档/包线）能到位到哪档；模型进程可否脚本拉起/停止/清态  
9. 整合 UI（§5.4）：接受"脚本版先行、UI 版并行"的节奏；UI 形态倾向桌面 GUI 还是 Web
