# ArduPilot 倾转旋翼 SIL / HIL 联仿需求说明（对外）

> 代码版本：Plane 4.6.x。  
> 目的：向外部仿真/动力学方说明联仿边界、通信差异与分阶段交付。  
> 详细技术实现见：`APM-MATLAB联合仿真.md`、`APM-SITL仿真体系与JSBSim.md`、`docs/vtol_hitl.md`。

---

## 1. 项目目标

验证倾转旋翼 / QuadPlane 在真实 ArduPilot 控制律下的闭环行为。联仿分两阶段：

| 阶段 | 名称 | 目标 | 飞控跑在哪 | 外部仿真机职责 |
|:--:|------|------|------------|----------------|
| **一** | **SIL 消息流打通** | 先跑通“指令 ↔ 状态”闭环与仿真环境 | PC 上 SITL 进程 | 提供动力学 + 环境，按约定协议回传状态 |
| **二** | **HIL 真机串口闭环** | 在真实飞控硬件上验证 IO/时序/链路 | 真飞控板（如 Pixhawk） | 仍提供动力学 + 环境，经**串口**闭环 |

**阶段一成功标准**：能稳定收发、锁步/近实时不卡死、可解锁与基本模式切换；**不要求**一开始就把高保真气动/天气模型做全。  
**阶段二**在阶段一协议与字段对齐后再启动。

---

## 2. 关键前提：SIL 与 HIL 通信方式不同

| | 阶段一 SIL（外部联仿） | 阶段二 HIL（经典串口） |
|--|------------------------|------------------------|
| 飞控侧 | PC 进程 `arduplane`（真实固件逻辑） | 真 MCU 固件 |
| 物理链路 | **网口 UDP/TCP** | **飞控 UART / USB-串口** |
| 典型协议 | SITL `JSON` / JSBSim / AirSim 桥 | **MAVLink HIL**（或双方约定的串口帧） |
| 交换内容 | PWM/执行器指令 ↔ 传感器与机体状态 | 执行器指令 ↔ 传感器与机体状态 |
| 与板内 SimOnHW 关系 | 无关 | **不同**：SimOnHW 用板内 SITL 模型，可不接外部动力学机 |

> 请勿按“同一套协议换个口”理解。SIL 打通后，HIL 仍需单独约定串口协议、波特率与时序。

---

## 3. 职责边界

### 3.1 我方（飞控 / ArduPilot）

- 提供并运行 ArduPilot Plane（含倾转/VTOL 相关模式与参数基线）。
- 阶段一：提供 SITL 侧桥接（优先 `JSON` 对接 MATLAB；也可 JSBSim / AirSim）。
- 阶段二：提供真飞控板、串口物理连接与固件侧 HIL 接入方案。
- 负责飞控侧：EKF、控制律、飞行模式、任务、故障保护、GCS（MAVProxy/QGC）。
- 给出接口字段表、联调步骤、验收用例。

### 3.2 对方（动力学 / 仿真环境）

- **提供飞行动力学模型**（六自由度或等效）：接收执行器指令，积分得到姿态/速度/位置等。
- **提供环境条件接口**（至少可配置，阶段一可先简化）：
  - 风速 / 风向（机体或 NED）；
  - 可选：阵风、湍流、温度、气压基准、起飞点海拔等。
- 按约定协议回传传感器/状态包；保证时间戳单调、锁步时每拍必回。
- 阶段二配合串口侧收发与超时/重连策略。

### 3.3 阶段一对方**暂不必须**做到的

- 完整高保真气动数据库、全包线验证；
- 复杂天气场景（结冰、强对流等）；
- 视景/场景渲染（除非选 AirSim 且双方同意）；
- GPS/罗盘/气压计硬件级仿真细节（JSON 路径下飞控常由位置/姿态内部生成部分传感器，见现有 MATLAB 文档）。

## 4. 阶段一（SIL）：消息流与环境打通

### 4.1 推荐对接路径（按优先级）

1. **MATLAB/Simulink + SITL `JSON`（推荐首选）**  
   - 文档：`APM-MATLAB联合仿真.md`  
   - 链路：UDP；SITL → 仿真机二进制 PWM 包（默认端口 **9002**）；仿真机 → SITL 一行 JSON 状态。  
   - 特点：**锁步**，利于复现与排障。

2. **JSBSim**  
   - 文档：`APM-SITL仿真体系与JSBSim.md`  
   - 链路：TCP 控制台 + UDP fgFDM；SITL 可拉起 JSBSim 子进程。

3. **AirSim**  
   - 适用于需要场景/视景时；接口见 `libraries/SITL/SIM_AirSim.*`。

> 阶段一请先选定**一种**路径打通；不要并行多套协议。

### 4.2 最小数据接口（阶段一必通）

**飞控 → 仿真机（每拍）**

| 内容 | 说明 |
|------|------|
| 执行器指令 | 典型 16 路 PWM（µs，约 1000–2000）；含倾转/电机/气动舵面通道映射需双方对齐表 |
| 帧序号 / 建议步频 | 用于丢帧、重复帧、重启检测（JSON 路径有 `frame_count` / `frame_rate`） |

**仿真机 → 飞控（每拍，最小集）**

| 字段 | 含义 | 备注 |
|------|------|------|
| `timestamp` | 仿真时间 | 单调递增 |
| `imu.gyro` | 角速度 | 机体系，rad/s |
| `imu.accel_body` | 比力/加速度 | 机体系，m/s² |
| `attitude` 或 `quaternion` | 姿态 | 二者择一 |
| `velocity` | 速度 | NED，m/s |
| `position` | 相对起飞点位移 | NED，m |

**环境（阶段一建议就预留，可先给常值）**

| 字段 | 含义 | 阶段一要求 |
|------|------|------------|
| 风速矢量或风速+风向 | 风场 | **可配置**；初值可为 0 |
| （可选）`airspeed` | 空速 | 有则直接用，无则可由速度推算 |
| （可选）起飞点经纬高/航向 | 原点 | 与 SITL `--home` 一致 |

通道映射（倾转舵机、电机、气动舵面编号）在联调前用一张表锁定，避免“消息通了但飞机飞不对”。

### 4.3 阶段一验收（消息流 / 环境）

1. **链路**：连续 ≥10 min 无协议卡死；锁步路径下飞控步频稳定。  
2. **字段**：最小状态集齐全；错误包可检出（magic/长度/JSON 解析失败有日志）。  
3. **控制**：可解锁；至少一种 VTOL/固定翼相关模式能切到并保持；油门/倾转通道变化时仿真状态有合理响应。  
4. **环境**：风速设为 0 与设为非 0（如 5 m/s）时，状态响应可区分（阶段一不要求气动精度）。  
5. **记录**：双方能保存同一段日志（飞控 DataFlash/MAVLink + 仿真侧 CSV/MAT），便于对照。

## 5. 阶段二（HIL）：真飞控串口闭环（概要）

在阶段一字段与通道映射稳定后启动。

| 项 | 要求 |
|----|------|
| 硬件 | 目标飞控板 + PC（跑仿真机） |
| 物理口 | 飞控 **UART 或 USB-CDC 串口** 至 PC |
| 协议 | 优先 **MAVLink HIL**（执行器指令 ↔ 传感器/状态）；若用自定义帧须书面约定 |
| 待双方确认 | 波特率、端口、锁步或实时、超时重发、CRC、通道顺序与 SIL 是否一致 |
| 验收方向 | 真板调度下闭环可飞；串口负载与延迟可接受；与 SIL 同场景趋势一致 |

> 板内 **SimOnHW**（`docs/vtol_hitl.md`）是另一条 HITL 路径：动力学在板内，**不替代**本阶段“串口外接外部仿真机”的需求。

## 6. 请对方确认 / 回复的清单

请直接回复下列选项，便于排期：

1. 阶段一仿真引擎：**MATLAB / JSBSim / AirSim / 其他（请写明）**  
2. 是否接受阶段一走 **SITL JSON 锁步**（推荐）  
3. 动力学模型当前成熟度：仅刚体 / 已有气动 / 含推进与倾转  
4. 风场接口：常值风是否够用阶段一；阵风/湍流是否阶段二再做  
5. 执行器通道数与映射表负责人（谁出第一版）  
6. 阶段二串口：是否按 MAVLink HIL；目标波特率  
7. 联调环境：同机还是跨机 IP；防火墙/端口是否可开 9002 等
