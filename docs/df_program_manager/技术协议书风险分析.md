## 二、协议核心需求与 APM 实现对照

### 2.1 硬件需求（协议 5.1.1 & 5.1.5.1）

| 协议要求 | APM 生态现状 | 评估 |
|---|---|---|
| 主 CPU ≥480MHz | CubeBlack STM32H7@480MHz、Pixhawk6X STM32H7@480MHz | ⚠️ 刚好达标，定制板可选 H7 双核 |
| 从 CPU ≥24MHz | 多数板有 STM32F100 协处理器（IOMCU），24MHz | ✅ |
| 内置 MEMS+动静压 | Pixhawk6X 内置双 IMU+气压计；动静压需外部传感器 | ⚠️ 需集成 |
| ≥2 路隔离 CAN | CubeBlack/Pixhawk6X 双 CAN | ✅ |
| ≥5 路 UART | 典型 6 路 UART | ✅ |
| ≥4 DI/DO 或 16 PWM | 典型 8-16 PWM + GPIO | ✅ |
| 内置 ≥8GB 数据记录 | `AP_Logger` 支持 SD 卡（`libraries/AP_Logger/`） | ✅ 需确认容量 |
| 总重 ≤2kg | 标准飞控板 + 外设 <2kg | ✅ |
| -40~+60°C | 工业级板（CubeBlack 标称 -20~+60°C）需验证低温 | ⚠️ 需确认 |
| 一体化设计 | 可能需要定制 `hwdef.dat` | ⚠️ 见 R2 |

**APM 板级定义**：`libraries/AP_HAL_ChibiOS/hwdef/`（366 个板子目录），每个含 `hwdef.dat` 硬件定义脚本，构建时由 `chibios_hwdef.py` 生成 C 头文件。

### 2.2 飞行控制功能（协议 5.1.3）

| 协议要求 | APM 对应实现 | 代码路径 | 评估 |
|---|---|---|---|
| **旋翼·增稳** | QSTABILIZE 模式 | `ArduPlane/mode_qstabilize.cpp` | ✅ |
| **旋翼·定高** | QHOVER 模式 | `ArduPlane/mode_qhover.cpp` | ✅ |
| **旋翼·定点** | QLOITER 模式 | `ArduPlane/mode_qloiter.cpp` | ✅ |
| **旋翼·航线** | AUTO + Q 模式 | `ArduPlane/mode_auto.cpp` | ✅ |
| **前向转换** | `SLT_Transition::update()` 三阶段 | `ArduPlane/quadplane.cpp:1466-1671` | ⚠️ 基础完备，安全中断需补强（R4） |
| **后向转换** | `transition->VTOL_update()` | `ArduPlane/quadplane.cpp` | ⚠️ 同上 |
| **冗余操纵分配** | `tilt_compensate_angle()` | `ArduPlane/tiltrotor.cpp:451-497` | ⚠️ 有基础但需定制 |
| **固定翼·姿态** | FBWA/ACRO 模式 | `ArduPlane/mode_fbwa.cpp` | ✅ |
| **固定翼·外环** | CRUISE/LOITER/AUTO | `ArduPlane/mode_cruise.cpp` 等 | ✅ |
| **自动垂直起降** | QTAKEOFF/QLAND | `ArduPlane/mode_qtakeoff.cpp` / `mode_qland.cpp` | ✅ |
| **倾转控制** | 4 种倾转类型 | `ArduPlane/tiltrotor.cpp` | ✅ 完备 |

### 2.3 CAAC 合规（协议 5.1.3.6）— 最大合规风险

| 协议要求 | APM 现状 | 评估 |
|---|---|---|
| 实名登记 + UOM 平台激活校验 | **无** | ❌ 需从零开发 |
| 运行识别信息报送 | **无** | ❌ 需从零开发 |
| 广播式 Remote ID（BLE/WiFi） | **无** | ❌ 需外部模块 |
| 网络式 Remote ID（4G/5G→UOM） | **无** | ❌ 需蜂窝链路集成 |
| 识别失效处置（禁飞/返航） | 可复用 failsafe 框架 | ⚠️ 需定制 |
| 身份鉴别与证书管理 | **无** | ❌ 需从零开发 |

**关联标准**：GB 46761-2025（实名登记和激活）、GB 46750-2025（运行识别）。

### 2.4 安全管理（协议 5.1.3.7）

| 协议要求 | APM 对应实现 | 代码路径 | 评估 |
|---|---|---|---|
| 低电量保护 | `handle_battery_failsafe()` | `ArduPlane/events.cpp:243-319` | ✅ |
| 电子围栏 | `AC_Fence` | `libraries/AC_Fence/` | ✅ |
| GNSS 丢失保护 | GPS failsafe | `ArduPlane/events.cpp` | ✅ |
| RC 中断保护 | short/long failsafe | `ArduPlane/system.cpp:353-418` | ✅ |
| 高度异常保护 | 需定制 | — | ⚠️ |
| 失速保护 | `AP_AdvancedFailsafe` | `libraries/AP_AdvancedFailsafe/` | ⚠️ 部分 |
| 单电机失效 | Copter 有 `throttle_boost`，Plane QuadPlane 较弱 | `libraries/AP_Motors/` | ⚠️ 需补强 |
| 余度管理 | EKF3 多 lane；板级余度调研中 | `docs/redundancy_feasibility.md` | ⚠️ 未实现 |

### 2.5 仿真验证（协议 5.1.4）

| 协议要求 | APM 对应能力 | 评估 |
|---|---|---|
| 全流程飞行仿真 | SITL + MAVProxy | ✅ |
| 控制参数拉偏 | 改 PID 参数重跑 | ✅ |
| 升阻/舵效拉偏 | 内置模型不易拉偏，需改源码或走 JSBSim/MATLAB | ⚠️ |
| 重量/重心拉偏 | SITL 参数可调 | ✅ |
| 风扰动 | `SIM_WIND_*` 参数 | ✅ |
| 传感器扰动 | `SIM_GPS_*`/`SIM_IMU_*` 噪声参数 | ✅ |
| 半物理仿真 | HIL 可做 | ✅ |
| 鲁棒性仿真矩阵 | 需自动化脚本 | ⚠️ 工作量大 |

## 三、风险点清单

### 🔴 高风险

| # | 风险 | 协议条款 | 详细说明 | 建议 |
|---|---|---|---|---|
| **R1** | CAAC Remote ID 合规 | 5.1.3.6 | APM 完全没有实名登记/UOM 对接/广播式+网络式 Remote ID 功能。涉及国标合规验证、与民航平台数据协议对接、证书管理、BLE/WiFi 广播模块集成。非飞控算法问题，是法规+通信协议问题 | 尽早与 CAAC/UOM 确认接口规范；评估第三方 Remote ID 模块（如大疆方案）是否可集成；预留独立 MCU/通信模块做 Remote ID |
| **R2** | 飞控硬件定制设计 | 5.1.1.1 | 协议要求"一体化设计"，可能需要定制飞控板。`hwdef.dat` 板级定义需新写，硬件设计+打样+验证周期长 | 一期即锁定硬件选型；优先评估 CubeBlack/Pixhawk6X 是否满足；如需定制则并行启动 |
| **R3** | 二次开发 API 与文档体系 | 5.1.3.2 | APM 虽有完整 HAL 和单例 API，但文档化程度远未达到"甲方可独立二次开发"水平。17+ 份文档交付工作量巨大 | 指定专人负责文档编写；优先产出 API 手册和快速入门指南 |
| **R4** | 过渡段安全处理 | 5.1.3.4 | 协议要求"转换进入条件、中断判断、安全性处理"。APM 过渡状态机有超时失败处理（`quadplane.cpp:1466-1671`），但缺少主动中断并回退的完整逻辑。300kg 级倾转旋翼过渡段气动不确定性大 | 在 `SLT_Transition::update()` 中增加中断回退分支；增加过渡走廊实时监控；SITL+HIL 充分验证 |

## 五、核心建议

1. **CAAC Remote ID（R1）**是最大合规风险，建议尽早与 CAAC/UOM 平台确认接口规范，或评估第三方模块集成
2. **动力学建模（R7）**决定仿真验证（R6）质量，内置 SITL 模型保真度不够，需甲方提供验证机气动数据
3. **过渡段（R4）**是试飞最大技术风险，APM 三阶段状态机是良好起点，但"中断回退"和"冗余操纵分配"需针对性开发
4. **一期仅 21 天**，建议优先锁定硬件选型和飞控总体方案
5. **文档交付**（R3）工作量大，建议一期即开始编写 API 手册框架
